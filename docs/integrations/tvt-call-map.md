# TVT 핵심 연동 호출 맵 — SuperLive Plus 1.18.1

기준 APK: SHA-256 `f57ff98226fcc7a0ec3587b077d5538facb57cc5b713a0938d1ee02b0f72f281`. 이 표는 **서비스 연동 핵심 경로**에서 확인된 Java→JNI 연결과 그 한계를 기록하며, APK 전체 기능 목록은 아니다. 전체 기능 감사는 [별도 기준선](apk-audit/00-coverage-baseline.md)과 기능별 보고서를 참조한다. ELF 오프셋은 `arm64-v8a` 라이브러리의 `st_value`다. 증거 표기의 해석과 도구·ABI 정보는 [정적 분석 보고서](superlive-static-analysis.md)에 있다. **확신도 높음**은 선언·호출·JNI 심볼 또는 Ghidra 의사코드가 일치함, **중간**은 호출 지점은 확인되지만 네트워크 결과/내부 분기는 미확정임을 뜻한다.

## 공통 수명·콜백 규칙

`TVTOpenSDK.init()`는 `startProtoManagerServer` 후 `registerCallback`을 호출한다. `request(route, JSON, TVTOpenCallback)`는 UUID를 발급하고 콜백을 맵에 저장한다. 네이티브 응답은 `*Reply(UUID, response)`로 돌아와 `getCallback`에서 맵 항목을 제거하고 `reply(route, response)`를 호출한다. `destroy()`는 서버를 중지한다. `NetClientProtocal`은 연결 ID와 task ID별 콜백을 별도 맵에 저장하고 `OnNetClientConnect`/`OnNetClientTaskData`/`OnNetClientTaskErr`로 전달하며, `CloseLiveStream`, `CloseLiveTalkBack`, `DisconnectEx`에서 맵 항목을 제거한다. 콜백이 호출되는 스레드와 네이티브 버퍼 소유권은 아직 확인되지 않았다. 근거: `J:com/tvt/protocol_sdk/TVTOpenSDK.java:207,2475-2496,2797-2809`, `J:com/tvt/network/NetClientProtocal.java:125-180,256-275,378-388`.

## T31에서 검증할 순서

1. 동일 앱/ABI와 승인된 테스트 계정·TVT 장치에서 로그인 응답과 토큰 유효기간을 확인한다. 보고서에 계정값·토큰을 기록하지 않는다.
2. 계정 채널 목록과 장치 내부 채널 번호/UID를 대응시키고, `ConnectDevByToken`의 연결 상태 및 LAN/P2P/relay 선택 결과를 기록한다.
3. `RequestLiveStreamTask`의 task ID, 프레임 콜백의 `byte[]` 길이·키프레임·타임스탬프·encodeType, 정지/재접속 수명을 추적한다. H.264/H.265 양쪽에 실제 프레임 증거가 있는 경우에만 지원으로 기록한다.
4. 알람 목록 응답과 push/실시간 통지를 구분해 시간·중복·권한을 확인한다. Talk은 시작·G.711 데이터·중지·권한 실패를 별도 기록한다.

현재 G10 `static_status=completed`, `runtime_status=pending`. 위의 확인된 Java/JNI 결합은 API 계약 후보일 뿐이며, 실제 TVT 어댑터의 성공 판정은 T31 런타임 증거를 사용한다.
