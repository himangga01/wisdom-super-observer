## Transport, credentials and callback rules

Internal `/sdk/...` IDs are Java dispatch routes. The concrete paths below are **POST JSON operation paths** appended to the configured account base, including its `/mobile_v1.0` prefix when selected by configuration. Ordinary calls reach `ProtoSdkManager::addHttpTask` at `N:0x2d6804`, `HttpsRequestTask::createPostJson` at `N:0x2cc3f0`, and the existing HTTPS POST transport. Header: `Content-Type: application/json;charset=UTF-8`. Authentication is the current **USER token in `basic.token`**, not a fabricated Authorization bearer header, P2P token or device-access token. The task builder includes a token when present; most operation functions do not themselves reject an empty token. The web worker must require a valid managed USER session for this slice.

The ordinary envelope is `basic:{ver:"1.0",id:decimal-task-id-string,time:Unix-seconds-integer,nonce:integer,token:USER-token}` plus the operation's `data` when constructed. The paths in the read-only table do not derive a password proof, AES payload or `basic.sign`. Do not copy bind's special signing into them. Basic-only functions pass an empty operation string; do not invent `data:{}` for those functions. Preserve the accepted account transport's isolated worker, TLS, bounded responses, endpoint allowlist and cancellation handling.

Native DC redirect parsing (`N:0x2ca898`) consumes `chain`, `domain`, `dcIp`/`ip`, `dcPort`/`port`, `httpPrefix`. It is not authority to request an arbitrary browser-supplied host. Device DC query is a distinct read, POST `/busops/resource/dev-dc/query` with `data.sn`, `N:0x2fd854`; it does not automatically move a USER session or authorize LAN access. Region/brand origins must stay bound to the managed identity's configured endpoint. No region-specific successful request was observed.

`TVTOpenSDK.request` allocates a UUID and stores a callback; JNI retains a named reply and the UUID, then dispatches through the DeviceProtoAPI or UserProtoAPI vtable. `getCallback` removes the callback before delivery. Synchronous native guard failure can return zero without delivering an error; absence of a reply is not an empty list. Java has no complete wrapper timeout recovery. The web implementation needs a deadline and exactly one terminal outcome, and must discard callbacks from obsolete identity/session generations.

`J:defpackage/q63.java:41–74,93–95,111–157` parses top-level transport `code`, then `basic.msgcode`. The five object consumers use `q63.b` (with the same fallback also present in `q63.c`) and take `data` with an `array` fallback. The account channel array consumer uses `q63.d`, which reads `data` only and never falls back to `array`. Transport values 35,28,6,7,400,404,500 may be normalized as network errors; disconnected Android networking also overrides the code. `bm3.java:18–40,57–62`, `qo3.java:12–33`, `vm3.java:19–20` select business success **200**. Codes **7000,7003,10002,11101,7004,7009,7088,7089,7090** emit global event 65634 rather than the ordinary local failure callback. A null wrapper/reactive error produces -100. These are parser/dispatch behaviors, not a complete business error dictionary.

Web success must require acceptable HTTP status, business 200, and a valid operation shape. Null/malformed success payloads are `PROTOCOL_ERROR`, never empty-directory success. Session-invalid outcomes stop admission and trigger the existing serialized session recovery/invalidation policy; ordinary denials preserve upstream numeric code privately. A timeout is `UNAVAILABLE` for a read and must not erase previously authorized snapshots. A write admitted upstream followed by timeout is `UNKNOWN_OUTCOME` and requires reconciliation.

## Shares: readback, permissions and mutations

Reachable sent/received consumers are `J:defpackage/gk2.java:145–225,230–261`, through `SendSharedChlFragment` and `ReceivedSharedChlFragment`. They parse `SendSharedBean`/`ReceiveSharedBean`, each `total:int,records:...[]` (`J:com/tvt/user/model/bean/SendSharedBean.java:10–13`, `ReceiveSharedBean.java:10–13`). Do not persist `childList`, selection state or computed support lists as server-authoritative grants: `ReceivedSharedChlFragment.java:166–234` groups rows by SN, constructs parent rows, and filters child rows by status. `J:com/tvt/user/model/bean/AuthConstants.java:8–18` defines exact verbs: **`live.video`, `live.audio`, `rec.video`, `rec.audio`, `ptz`, `talk`, `alert`, `arm`, `config`**, plus older **`live`**, **`rec`**. `ReceiveShareIPCDetailActivity.java:107–175` has a distinct legacy branch when `live.video` is absent: for local model category 13 that branch hides alarm and Talk, then returns. Actual authorization requires the intersection of actor/store grant, identity linkage, current share, permitted channel/action and device support.

### Serial, QR, LAN and AP paths

There are distinct QR payload families. Device info QR generation emits the structural text `<sn>…</sn><user>…</user>` (`J:com/tvt/devicemanager/DeviceQrcodeActivity.java:125–129`). This is not a URL and does not itself bind a device. The separate local-device sharing QR is JSON `v:"QR10",data:base64,eyp:int,crc:long,scrlen:int` (`J:com/tvt/dev_share/bean/QrcodeImgBean.java:8–29`). `ShareDeviceUtils.java:91–101,128–145,159–164` decodes base64; nonzero eyp uses `OpensslSDK.AESDecryptECB` with a supplied passphrase and truncates to scrlen, then trims text and verifies native CRC32. Empty passphrase generation uses unencrypted base64 and eyp=0. The exact AES key derivation/padding and native CRC parameters need offline decoding before a compatible encrypted QR implementation.

The QR's inner local-device model uses `AD,DN,UN,PW:string` and `PT,HS,ETY:int` (`ShareDeviceBean.java:8–29`); these include credentials. Neither raw QR text nor decrypted PW belongs in browser logs, analytics or public examples. `ShareDeviceUtils.calculateQrcodeSize` checks a **1500-byte** default-charset bound; this is a generation helper, not evidence that all import paths enforce it. Web import must bound before base64/decrypt and check scrlen against decoded size.

`J:com/tvt/network/GlobalUnit.java:1713–1715` classifies SN-like input using the exact source regex `^[a-zA-Z0-9]{1,128}$`. `AddDeviceActivity.java:98–104` appends `:PT` only when that classifier fails; `ShareDeviceUtils.java:70–82` has a separate address/port duplicate check. This classifier is not DNS/IP/URL validation. A web gateway needs explicit host/port canonicalization and permitted-network policy, preserving the distinct SN route; do not send arbitrary QR addresses from the hosted worker. The full manual form validation and every OEM QR format are not yet decoded.

Local list menu `LocalDeviceActivity.java:2425–2451` distinguishes LAN search, QR sharing, and sort choices. LAN search runs `DeviceManagerSearchLocalActivity`, not account HTTP. Doorbell AP flow is `WifiConfigInputActivity → WifiConfigConnectActivity → jx0` (`J:com/tvt/devicemanager/doorbell/WifiConfigInputActivity.java:66,95–111`; `WifiConfigConnectActivity.java:197–335`; `J:defpackage/jx0.java:152–190,461–465`). ## Proposed implementation slices and acceptance fixtures

1. **W07 read directory worker/RPC slice:** add typed operations for account devices, channels, detail and sent/received shares to the existing account worker boundary, with a separate reviewed scope. The API supplies protected identity/store selectors, never token/header/origin. The worker resolves USER credentials and endpoint from its managed ticket, rejects a revoked session before I/O and again before publishing results, and returns bounded typed observations. No direct browser cloud access. A new family RPC and persistence extension remain implementation work.
2. **W07 service/persistence slice:** maintain identity/device/channel/store links and separate incoming share grants. Never give every account device to every tenant/store. Internal UUID resolution must check actor, tenant, managed identity, store link and requested channel. Preserve upstream SN/ID domains and page completeness; reconcile deletion only from a complete valid snapshot. Apply generation changes atomically with grant revocation. Return stale-but-labeled observations only where policy permits, never stale permission as current authorization.
3. **W08 handoff:** expose authorized channel index/name, model/firmware and observed capability metadata to the single T17/T31 adapter. Online state remains unknown until verified detail/session observation; stream open and device credential access recheck grants. W04 retains native handles and W08 retains media leases. No second camera adapter or per-tile account login.
4. **Later write slices:** (a) names/favorites/groups with readback; (b) new share creation/accept/delete with owner/recipient reconciliation; (c) friend/application/group operations with involveShare effects; (d) bind/transfer/unbind after special crypto/ownership readback decode; (e) local credential synchronization and QR/LAN/AP through W12. Each slice has its own intent/fence/readback tests. Unresolved operations return explicit unsupported/unavailable states before upstream admission, never a generic success object.

Required synthetic negative fixtures: missing/null/wrong-type records; string total versus integer share total; duplicate SN/channel IDs; page zero and negative values; server total larger than fetched records; channel list containing an unrequested SN; stale or cross-identity callback; revoked ticket during HTTP; wrong tenant/store/channel UUID; incoming row pending or missing auth; legacy auth lacking exact new verb; one channel permitted and sibling denied; malformed detail capability; unknown online status; unknown resourceType; directory failure without destructive cache clearing; alternate shared-list callback label mismatch; empty channel input without a native callback; register/ability JNI with no dispatch; writes timing out after admission; owner revoke while recipient live lease exists; batch partial results; involveShare true/false; malformed QR base64/CRC/scrlen/oversize; QR local network address without a gateway. Fixtures use invented values only. No fixture in this document has been run against APK or server.
