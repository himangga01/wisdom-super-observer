## Supported wire layouts

All multibyte numeric fields below are little endian. GUID bytes use the source `GUid.l()` representation: Data1 uint32, Data2/3 uint16, then eight unchanged bytes. The default client GUID is zero, matching `cw3.V2 = GUid.e()`.

Source parser consumes60 bytes; final four transport bytes are ignored. Other greeting fields remain uninterpreted. |

## Credentials, proofs and recovered crypto

`Credentials` preserves username/password exactly, with strict UTF8 encoding, no trimming or case changes. Both fields reject embedded NUL, malformed Unicode and encoded lengths over63 bytes; username must be nonempty. This is an explicit conservative termination policy for the source's64-byte arrays, not evidence of actual device limits. An empty password requires `allow_empty_password=True`; its MD5 representation is the source empty string. Nonempty password MD5 is uppercase hexadecimal.

Security0 sends the raw password padded with zeros. Security1/2 legacy proof is SHA1 of uppercase-MD5 text concatenated with the device challenge formatted as eight decimal digits. Newer ordinary proof is SHA512 of uppercase-MD5 text + `#` + the unpadded decimal challenge. For security2, username bytes are XORed with repeating **unpadded** decimal challenge bytes only when the username byte is nonzero and unequal to the mask byte. Zero padding is retained; XOR-equal bytes are retained. Challenge0 uses mask text `0`.

Client nonce generation uses `secrets.choice("123456789")` eight times. The injectable nonce provider must return exactly eight ASCII nonzero decimal digits. Nonces are generated only when security is enabled. Legacy replies verify SHA1 of uppercase-MD5 text + unpadded decimal client nonce using constant-time comparison before returning the key.

The selected APK ARM64 `libOpensslSDK.so` was copied to a new isolated Ghidra project for **static analysis only**. Complete targeted bodies recovered:

The Python codec uses the existing `cryptography` dependency to generate the same RSA parameters and public PEM. Since Java first Base64-encodes reply ciphertext and native immediately decodes it, Python decrypts the original128 bytes directly. Decrypted key text must be nonempty, at most117 bytes, strict UTF8 and NUL-free. The codec preserves exact bytes; it does not guess a hex width or implement subsequent AES interpretation. Newer key extraction does **not** establish server credential proof: `proof_verified=False`, even after valid RSA decryption. Later authority must not rely on decryption or the success action alone. The source's separate dynamic/share `S4/T4/U4` branch is rejected as `UnsupportedBranch("dynamic_share")`; its distinct proof and credential recovery are outside ordinary SN plus device credentials.

## Stable private transport boundary

```python
credentials = Credentials(username, password)  # private trusted input only
greeting = parse_greeting(exact_64_bytes)
handshake = LoginHandshake(
    generation=generation,
    sequence=sequence,
    credentials=credentials,
    client_guid=guid_wire_bytes,       # default zero16
    client_address=address_four_bytes, # default zero4, caller supplies if needed
    client_type=reviewed_client_type,  # default0 = source GlobalUnit.J0
)
request = handshake.build_request(greeting)  # PrivateWire.data
stream = N9000Stream(greeting=greeting)
for packet in stream.feed(private_transport_chunk):
    result = handshake.accept_reply(packet, generation=generation)
    if result is None:  # exact2561/2562/2563 startup event; login remains pending
        continue
    # A matching login result still requires later serial/permission joins.
```

The transport must collect and split the initial greeting before using `N9000Stream`, pass that validated greeting to the production stream, enforce the caller's monotonic timeout, handle partial sends, retain sequence/generation, and close both state objects on disconnect or a parser failure. `LoginHandshake.close()` releases private credential/key references and makes the attempt terminal. Immutable Python bytes cannot promise memory erasure. The parser is owned by one generation and cannot be reused after failure. The overall deadline must continue while notifications are skipped; a notification is not progress toward credential acceptance.

`N9000Stream` defaults: maximum total ordinary packet65536 bytes, incoming chunk65536 bytes, fragment count256. Configurable hard ceilings are1MiB per packet/chunk and4096 fragments. Limits are checked before receive copying/assembly; fragmented totals include the inner header. Mutable caller input is copied and never changed. The handshake independently caps reply body65512 bytes, even if a larger stream bound is configured.

Private immutable records are `Greeting`, `Packet`, `PrivateWire` and `LoginResult`; credentials/key objects use immutable slots. All private types redact repr and reject pickle, and no public JSON adapter exists. Fields such as wire bytes, MD5, proof, session GUID, key bytes and channel tail are trusted private transport inputs/outputs, never public diagnostics. Generic object introspection/dataclass conversion must not be used as a public serializer. Each nonce/RSA provider call replaces provider-raised `Exception` values, including `CodecError` subclasses, with a fresh fixed `CodecError` from None and terminates state. Subsequent internal return validation preserves its typed diagnostics.

State is `new` → `awaiting_reply` → `terminal`, for both accepted and rejected replies. Repeating a request is forbidden. `accept_reply` returns `None` only for an exact2561/2562/2563 startup shape after validating the pending attempt and generation; state remains `awaiting_reply`. A stale generation, login sequence mismatch, wrong reply action/command, malformed notification/reply, failed legacy proof, failed RSA extraction or genuine failure action ends the attempt. Failure action2 is parsed as `oz0`, with its error value at body0; success field `b` at16 is ignored. There is no automatic password retry.

`Packet.peer_version` preserves the exact incoming header value. `LoginResult` exposes `device_guid`, `session_guid`, `key_material`, `channel_tail`, `reply_proof`, `proof_verified`, `key_extracted` and the accepted reply's `peer_version`, all private. An unsolicited header does not pin that final value. `serial_validated`, `authorized` and `live` remain false. Security0 success action is explicitly not authenticated. Newer RSA decryption is explicitly not authenticated. Even verified legacy proof is not permission/channel authority or live acceptance.
