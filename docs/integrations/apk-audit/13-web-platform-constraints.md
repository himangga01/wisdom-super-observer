# SuperLive Plus 1.18.1: 웹 플랫폼 기능 동등성 제약

조사일: 2026-09-27. 범위: 보존된 APK의 **정적** 분석 결과 [01](01-ui-feature-inventory.md)–[10](10-completeness-review.md), 일부 원본 Manifest/JADX 경로, 브라우저·Android·OAuth의 공식 문서. 계정 로그인, 기기 설정, 푸시 발송, 마이크·카메라 사용, 서비스 호출은 하지 않았다. 여기서 **가능**은 웹 플랫폼에 대응 수단이 있다는 뜻이며, TVT 서버·기기에서 성공했다는 뜻이 아니다. **동등성**은 사용자 결과와 실패/복구 동선으로 판정해야 한다. Android의 권한·백그라운드 실행 방식까지 동일하게 복제하는 목표는 브라우저만으로 성립하지 않는다.

`J:`는 `C:\wso-private\superliveplus\1.18.1-2026-09-27\jadx-full\sources` 아래의 경로/줄, `M:`은 같은 원본의 `apktool/AndroidManifest.xml` 줄이다. 각 표의 웹 근거는 링크된 공식 문서다. 브라우저 지원은 버전·OS·설치 상태에 따라 달라지므로 실제 대상 조합에서 확인해야 한다.

## 웹 동등성 판정의 선행 조건

1. TVT `/sdk/*` 문자열은 앱 내부 JNI 라우트이며 공개 REST URL이 아니다. Android `.so` 또는 TVT의 TCP/UDP 프로토콜을 페이지 JavaScript로 바로 호출할 수 있다는 근거도 없다. 계정·기기·푸시·미디어 게이트웨이의 **합법적 사용 가능성, 인증, wire 계약**부터 별도로 확인한다. [02](02-protocol-api.md), [08](08-native-abi-jni.md), [09](09-auth-network.md).
2. 웹 공개 원점은 HTTPS로 계획한다. Service Worker, Push, 마이크·카메라, Web Bluetooth 등의 권한 API는 [secure context](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts/features_restricted_to_secure_contexts)에 묶이고, 권한은 사이트 원점 및 사용자의 선택에 따른다. 앱 Manifest의 권한 선언은 웹 권한으로 이전되지 않는다.
3. 같은 사용자 결과라도 `브라우저 열린 상태`, `백그라운드/종료`, `설치형 PWA`, `iOS 홈 화면 앱`, `권한 거부`, `오프라인`을 따로 판정한다. iOS/iPadOS 웹 푸시는 [홈 화면에 추가된 웹 앱](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)에서 사용자의 직접 조작 후 허용된다. 브라우저 탭만 열린 경우와 같은 전제조건으로 세면 안 된다.
4. 기기 모델, 지역/브랜드, 펌웨어, 계정 권한에 따라 APK의 메뉴와 결과가 달라진다. [10](10-completeness-review.md)의 정적 복원 공백과 서버/기기 미검증 범위를 그대로 유지한다.

## 동등성 결론 및 우선 검증 순서

**브라우저 단독으로 Android와 같은 플랫폼 동작을 요구하면 판정 불가 또는 불가인 항목**은 (1) 잠금 화면의 자동 전체화면 도어벨 통화, (2) 종료된 웹 페이지가 유지하는 자체 TVT TCP 소켓/foreground service, (3) 도어벨 AP 자동 접속과 raw TCP 9008 Wi-Fi 설정, (4) 앱 개인 저장소의 무제한 스캔/삭제, (5) Android WebView Java bridge 직접 사용이다. 이에 대한 사용자 기능은 서버 중계, 사용자의 명시적 OS 조작, 공급사 웹 API 또는 동반 앱으로 다시 계약해야 한다. 이는 기기/서버가 지원한다는 주장도, 그 대안이 이미 구현됐다는 주장도 아니다.

실제 개발 착수 전 시험 순서는 **(a)** 공급사/계정으로 인증된 웹 또는 게이트웨이 접근과 사용 권한, **(b)** 대표 기기 1대의 영상·Talk·알람·설정 응답/오류 계약, **(c)** 도어벨 초대→답/거절 및 푸시의 OS별 결과, **(d)** Wi-Fi 설정의 브라우저 외 동선, **(e)** 로컬 파일/결제/제3자 로그인의 원점·권한 계약이다. 각 시험은 기기 모델/펌웨어, 계정 역할, 브라우저·OS 버전, HTTPS 원점, PWA 설치 상태, 권한/네트워크 상태, 서버 시간/이벤트 ID, 기대 결과와 실제 결과를 남겨야 한다. 이 문서는 정적·공식 문서 기반 설계 제약이며 **100% 구현 가능성 또는 기능 성공 판정이 아니다**.
