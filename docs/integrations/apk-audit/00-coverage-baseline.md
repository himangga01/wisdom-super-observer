이전 Ghidra 심층 분석은 arm64 라이브러리 4개(`libProtoSDK.so`, `libNetClientProtocal.so`, `libNatTraveral.so`, `libH264Decode.so`)의 선택 경로에 집중했다. 전체 JNI·기능 판정은 나머지 라이브러리와 두 ABI의 대응 여부까지 별도로 점검해야 한다.

## 완료 판정 규칙

1. 앱 화면·메뉴·Manifest·리소스·모듈에서 발견한 기능을 빠짐없이 기능 목록에 올린다.
2. 각 기능을 `화면/리소스 확인`, `Java 호출 확인`, `JNI/네이티브 확인`, `실기기 동작 확인` 단계로 구분한다. 한 단계의 증거를 다음 단계의 성공으로 간주하지 않는다.
3. 라우트/요청 클래스, native 선언/내보내기, 라이브러리·ABI, 디컴파일 오류를 기계적으로 대조하고 차이를 모두 남긴다.
4. 실기기에서 확인하지 않은 서버 응답·영상·알람·음성·권한 및 계정별 차이는 미확인으로 표시한다.
5. 웹서비스의 기능 동등성 판단은 기능별로 한다. 정적 분석 완료나 기능 이름 발견만으로 100% 동등성을 주장하지 않는다.
