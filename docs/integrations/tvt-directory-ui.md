# Readonly TVT directory components

Date: 2026-10-03 (Asia/Seoul). Baseline: `b25df5268a6ff7b524232c7c62cf52bb1583061d`.

`DirectoryPage` is a named client-component export from `apps/web/src/features/tvt/devices/DirectoryPage.tsx`. Its exported `DirectoryPageProps` contract is `{ userId: string; bootstrap: Bootstrap; csrf: string; requery: () => Promise<Bootstrap> }`, matching the authenticated TvtShell Startup inputs. Pass the current Bootstrap and its existing requery callback; unmount on navigation. Startup route, menu and deep-link wiring are a separate task.

Only current Bootstrap linked identities are selectable. Selection is explicit, and each identity's returned brand and region are retained exactly. Consent must be accepted. No directory call runs on mount, selection or tab changes. Each active authority scope constructs the existing directory client once. Read buttons expose device list, channel list, device detail, selected channel detail, sent shares and received shares. Device/share pagination preserves zero-based native integers and zero page sizes. Refresh uses the displayed snapshot's last accepted page; query uses the form inputs. There is no automatic traversal or retry.

Actor, tenant, profile, consent version/status, account set, shell region/brand, CSRF and selected identity changes dispose entry state. Tab/device/channel selection cancels the relevant pending reads. Unmount, pagehide and the existing web logout form cancel owned requests. Controller ownership guards success, failure and finally so late promises cannot alter a replacement entry. Newer generation results clear every prior snapshot and abort other pending reads; older generation observations are discarded.

Transient failures retain accepted snapshots with visible refresh status. Denied scope failures clear all data and offer the existing web login, organization, account or consent recovery path based on the client's exact safe code. Fix1 stores denial at the active authority lifetime above disposable tab entries. TVT authentication/identity denial is retained per exact identity/region/brand tuple; another linked identity can be queried without erasing the denied identity's recovery. Web authentication, organization and consent denial apply across every identity in that authority context. Tab switching, deselecting/reselecting the same account and unchanged Bootstrap requery cannot reset denial or issue more directory calls. Consumed changed authority props create a fresh empty context that still requires explicit selection and query.

Requery is an explicit recovery action and never renews TVT tokens or adopts a data center. Unchanged Bootstrap alone does not silently authorize reuse of denied data. Recovery requery has its own disposal guard and synchronous lock: authority-wide recovery remains busy across view navigation, while a disposed identity's late requery cannot show errors or unlock its replacement.

Display helpers consume generated observation types without duplicating network schemas. Missing, null and opaque observations are unavailable; source defaults and private objects are never displayed. Names, opaque SN, native channel numbers and selected safe detail/share fields are rendered as text. Integer status values remain literal values; no online/offline interpretation is invented. Sent and received share fields remain distinct. Unknown-member counts, raw JSON, evidence internals, auth arrays and capabilities are omitted. Directory observations confer no control, media or mutation authority.

Korean controls use labels, native buttons/selects, keyboard interaction, busy/alert/status semantics, responsive cards and existing WSO Tailwind tokens. The approved visual reference guides card styling; direct Chrome screenshots and rendered styling acceptance remain root-owned.
