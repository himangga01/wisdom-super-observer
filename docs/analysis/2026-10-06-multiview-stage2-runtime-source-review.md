**Locations:** `root12-raw-owned.py:357–376`, `584–635`, `751–848`.

Session revocation and the owned DB context exit also have no final cleanup-phase elapsed classification in this helper.

The parent deadline is startup_seconds + the full live_seconds + twice cleanup_seconds. It is not the worker cleanup phase's bound. For example, a quick live pass leaves enough aggregate slack for a cleanup call to return True after its own limit; raw/observer/original retirement can all succeed and normal_cleanup stays True. Late readiness/completion can therefore avoid the startup failure classification when observed after the boundary.

**Consequence:** an overrun can be reported COMPLETE, contrary to the accepted separate phase bounds and the author's stated sticky failure rule. Original ownership retention itself is preserved; the defect is false normal acceptance after late settlement.
